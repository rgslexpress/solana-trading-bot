# Relatório de auditoria técnica

Data: 2026-10-21. Escopo: código existente (sem reescrita). **LIVE permaneceu bloqueado e nenhuma transação real foi assinada ou enviada.**

## Limites desta auditoria (leia primeiro)

- **Sem acesso à rede.** `dev.jup.ag`, `api.geckoterminal.com` e o PyPI estão bloqueados no ambiente (confirmado novamente). A comparação com a Jupiter/GeckoTerminal foi feita por **resultados de busca** que citam as páginas oficiais (links ao final), **não** abrindo as páginas nem chamando as APIs.
- **Testes com rede simulada não validam as APIs reais.** Eles provam que o código se comporta corretamente *dado* o contrato que eu assumi. Se o contrato real diferir, os testes continuarão passando.
- Todos os dados de backtest/paper são **sintéticos**. Nada neste relatório é evidência de rentabilidade.

## Respostas por item do pedido

**1. Jupiter.** Contrato assumido após esta auditoria (fontes por busca): base `https://api.jup.ag/swap/v2`; `GET /order` (`inputMint`, `outputMint`, `amount`, `taker`, `slippageBps`) com `x-api-key`; resposta com `transaction` (base64; `null` sem taker; `""` com erro → `errorCode`), `requestId`, `inAmount`, `outAmount`, `otherAmountThreshold`, `slippageBps`, `swapMode`, `priceImpact`, `lastValidBlockHeight`; `POST /execute` com `{signedTransaction, requestId}` → `status` Success/Failed, `code`, `signature`, `totalInputAmount/totalOutputAmount`, `inputAmountResult/outputAmountResult`; transação com market maker (JupiterZ) exige **assinatura parcial** (o código preenche só o slot da carteira). **Não pôde ser validado sem rede:** nomes exatos de todos os campos; que `slippageBps` é aceito em `/order` (fontes de terceiros + guia Ultra); **unidade de `priceImpact`**; existência de status "Pending" (relatado por um cliente da comunidade; tratado como desconhecido, sem reenviar); quais programas/discriminadores as rotas V2 usam de fato (por isso o modo estrito pode rejeitar transações legítimas até você rodar `scripts/dry_run_quote.py`).

**2. Segurança de transações.** O validador decodifica a transação serializada (cabeçalho, chaves, instruções, lookups), confere fee payer, signatários, programas (allowlist), cada instrução System/Token/ATA/ComputeBudget, destinos e valores de SOL, taxa de prioridade e argumentos do roteador. Ver achados 1–4; 11 testes negativos novos + 14 existentes. **Resíduo inevitável:** CPIs internas dos programas de roteamento não são visíveis; confiança no programa da Jupiter. O destino token-a-token dentro do swap é decidido pelo programa, não pelo cliente.

**3. Dados.** Não foi possível chamar a API real. Verificado por teste: detecção de dados defasados, lacunas, duplicatas, ordem, NaN, OHLC inconsistente, desalinhamento, candle em formação/recém-fechado. **Não verificado:** timestamps do Gecko são abertura do candle?; volume é da pool (não consolidado); `reserve_in_usd`; limite de ~30 chamadas/min vs. consumo do robô (várias chamadas por token por ciclo — pode estourar com muitos tokens). Use `scripts/check_data_provider.py`.

**4. Backtest.** Auditado: sem look-ahead (sinal no fechamento, execução na abertura seguinte; HTF só após fechar; recorte do futuro não altera trades passados), custos e slippage aplicados em ambos os lados e conferidos contra o livro, stop/gap por candles fabricados, contabilidade de caixa = livro, métricas conferidas à mão (profit factor, expectativa, drawdown, Sharpe), divisão temporal disjunta, walk-forward sem vazamento do teste. **Não representa fielmente a Solana:** liquidez fixa (sem histórico de pools), slippage como função linear simples, sem MEV/sandwich, sem taxas de prioridade variáveis, sem congestionamento, sem fills parciais; latência/falhas só via parâmetros não calibrados. Sharpe com candles majoritariamente "flat" (baixa exposição) é pouco informativo.

**5. Risco.** Exercitados no caminho de serviço: perda diária, perda acumulada → kill switch (persistente e em modo seguro após reinício), perdas consecutivas/cooldown e referência diária persistidas, reserva de SOL, estado desconhecido (reconciliação, bloqueio de entradas, kill switch por tempo), divergência de saldo, falhas consecutivas de execução, ausência de dados. Achados 5–6 corrigidos. **Lacuna conhecida:** a perda diária usa patrimônio marcado a mercado por preço do último candle fechado (não por tick).

**6. Testes.** Ver `RELATORIO_TESTES.md`: 143 executados, 143 passaram, 0 falharam. Não executados: `pytest` (não instalável), `ruff`, `mypy`, Docker, Python 3.12, qualquer chamada real.

**7. Pendências (priorizadas).** 1) validar a API real da Jupiter e o validador com transações reais (sem assinar) — **bloqueia o LIVE**; 2) validar provedor de candles/liquidez reais; 3) checar vetor de teste da derivação de ATA contra uma ATA real conhecida; 4) executar `pytest`/`ruff`/`mypy`; 5) take-profit parcial (funcionalidade, não segurança) e correlação com BTC (informacional) — **deliberadamente não implementados** nesta rodada para não ampliar a superfície antes de fechar os itens de segurança/integridade; 6) failover de RPC; 7) calibrar slippage/latência com dados reais.
